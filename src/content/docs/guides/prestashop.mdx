[PrestaShop](https://prestashop.com) with a MySQL database. The shop installs itself on the first start: you don't use the web installer. About 20 minutes, most of them waiting for the installation.

Everything below assumes you've done [Before you start](/guides/#before-you-start) once: Sirio installed, the proxy running, and a domain pointing at your server.

## 1. Prepare the files

Create an empty repository on GitHub (GitLab or Gitea work the same; a **private** one is fine and recommended, because the files will contain passwords). Then, on your computer:

```bash
git clone git@github.com:YOU/prestashop-sirio.git
cd prestashop-sirio
```

Create one file, `compose.yaml`. Change `PS_DOMAIN` to your domain, and `ADMIN_MAIL` to your email: they become your admin login.

```yaml title="compose.yaml"
services:
  prestashop:
    image: prestashop/prestashop:9.2.1-apache
    container_name: prestashop
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      PS_DOMAIN: shop.example.com
      PS_ENABLE_SSL: "1"
      PS_INSTALL_AUTO: "1"
      PS_LANGUAGE: en
      PS_COUNTRY: GB
      PS_FOLDER_ADMIN: backoffice
      PS_FOLDER_INSTALL: install-to-delete
      ADMIN_MAIL: you@example.com
      ADMIN_PASSWD: CHANGE-ME-1
      DB_SERVER: db
      DB_NAME: prestashop
      DB_USER: prestashop
      DB_PASSWD: CHANGE-ME-2
    volumes:
      - prestashop_data:/var/www/html

  db:
    image: mysql:8.4
    container_name: prestashop-db
    restart: unless-stopped
    environment:
      MYSQL_DATABASE: prestashop
      MYSQL_USER: prestashop
      MYSQL_PASSWORD: CHANGE-ME-2
      MYSQL_RANDOM_ROOT_PASSWORD: "1"
    volumes:
      - db_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  prestashop_data:
  db_data:
```

Replace every `CHANGE-ME…` with a different password of yours. To get a good one: `openssl rand -hex 24`. Where the same password appears twice, use the same value in both places.

`PS_DOMAIN` is the domain **without** `https://`. `PS_FOLDER_ADMIN` is the secret name of the administration folder: pick your own, it's your back office address.

When the files are ready, send them to the repository:

```bash
git add .
git commit -m "First version"
git push
```

## 2. Create the site and the domain in Sirio

In Sirio:

1. Open **Sites** → **New site**, type the name `shop` and press **Create site**.
2. In the site, press **New domain**, type `shop.example.com` (use your own domain) and leave **TLS** on *Automatic HTTPS (Let's Encrypt)*. Press **Add**.
3. Press **Check DNS**: it must show the public IP of your server. If it doesn't, fix the `A` record at your DNS provider first and try again in a few minutes.

## 3. Connect the repository

In Sirio:

1. Open **Repositories** → **Connect repository**.
2. **Git URL**: the address of the repository you just created. **Default branch**: `main`.
3. Public repository: choose *public repository*. Private repository: choose *HTTPS token* or *SSH deploy key* ([how](/docs/pipeline/#connecting-a-repository)).
4. Press **Connect**.

## 4. Create the pipeline

In Sirio:

1. Open **Pipelines** → **New pipeline**.
2. **Name**: `shop`. **Repository**: the one you just connected. **Site**: `shop`. **When to run**: *on request only* (you can change it to *on every push* later).
3. In the **Deploy** phase press **Detect from compose**. Sirio finds `compose.yaml` and adds a *Docker Compose* step with the command `up`.
4. Press **Save pipeline**.

## 5. Run the pipeline

1. In **Pipelines**, press **Run** next to `shop`, keep the default branch and confirm.
2. Watch the log. This run only starts the containers: PrestaShop then installs itself, which takes **3 to 5 more minutes** (open the `prestashop` container's log in **Containers** to follow it; it's done when it says it's starting the web server).
3. When the run turns green, open **Containers**: `prestashop` is there, running.

## 6. Point the domain at the container

1. Go back to **Sites** → `shop`.
2. On the `shop.example.com` row press **Route**.
3. **Path**: `/`. **Container**: `prestashop`. **Port**: `80`.
4. Press **Add**.

That's all: Sirio configures the proxy and the HTTPS certificate arrives with the first visit to `https://shop.example.com`. Don't publish any port in the compose file: the route reaches the container inside the server's network.

## 7. Finish in the browser

Open `https://shop.example.com`: your store is there, with the sample data of a new installation.

The administration is at `https://shop.example.com/backoffice` (the `PS_FOLDER_ADMIN` you chose), with the `ADMIN_MAIL` and `ADMIN_PASSWD` of the file.

Then remove the installer, which PrestaShop leaves in a folder with the name you chose in `PS_FOLDER_INSTALL`. In **Containers** open the `prestashop` container, press **Terminal** and type:

```bash
rm -rf /var/www/html/install-to-delete
```

## Updating

PrestaShop's own updates and its modules are done from the back office. For the container images, bump the number in `image:` (for example `9.2.1-apache` to a newer tag from [Docker Hub](https://hub.docker.com/r/prestashop/prestashop/tags)) and push.
Then, in **Pipelines**, press **Run** again. Your catalog, orders and uploaded images stays: it lives in named volumes, which a deploy does not touch.

## Backups

Create a backup plan for the site in **Backups** and include the volumes `prestashop_data`, `db_data`: see [Backups](/docs/backups/). Do it before you start adding real content.

## If something goes wrong

- **Blank page or 502 right after the run**: the installation is still going. Follow the container's log and wait.
- **Shop opens without styles or redirects to `http://`**: `PS_DOMAIN` has `https://` in it, or a different domain than the route's. It must be only the host name. After fixing it, delete the `prestashop_data` volume and run again, because the value is written during the first installation.
- **You want to start the installation over**: in **Volumes** delete `prestashop_data` and `db_data` (this erases the shop) and run the pipeline again.

- **A step fails or the run stays red**: open the run's log in **Runs**. A file Sirio refuses (for example a `ports:` line it can't allow, or a folder outside the repository) is named there, with the key. More in [Compose files and host access](/docs/security/#compose-files-and-host-access).

- **`502 Bad Gateway` or a connection error at the address**: the container isn't ready yet, or the route has the wrong container or port. Check both in **Sites**.

- **The certificate doesn't arrive**: the DNS must already point at the server (**Check DNS** in the site) and ports 80 and 443 must be reachable from the Internet.
