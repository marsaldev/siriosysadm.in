[Vikunja](https://vikunja.io) è un gestore di attività e progetti. Gira in un solo container, con il database SQLite integrato: la guida più semplice della serie. Circa 10 minuti.

Qui sotto si dà per scontato che tu abbia già fatto una volta [Prima di iniziare](/it/guides/#prima-di-iniziare): Sirio installato, il proxy attivo e un dominio che punta al tuo server.

## 1. Prepara i file

Crea un repository vuoto su GitHub (con GitLab o Gitea è uguale; meglio **privato**, perché i file conterranno delle password). Poi, sul tuo computer:

```bash
git clone git@github.com:TU/vikunja-sirio.git
cd vikunja-sirio
```

Crea un solo file, `compose.yaml`. Cambia l'indirizzo in `VIKUNJA_SERVICE_PUBLICURL` con il tuo dominio (tieni `https://` e la `/` finale).

```yaml title="compose.yaml"
services:
  vikunja:
    image: vikunja/vikunja:2.8
    container_name: vikunja
    restart: unless-stopped
    # I volumi nominati appartengono a root: senza questa riga Vikunja (utente 1000) non potrebbe scriverci.
    user: "0:0"
    environment:
      VIKUNJA_SERVICE_PUBLICURL: https://attivita.esempio.it/
      VIKUNJA_SERVICE_SECRET: CAMBIA-MI-con-una-stringa-lunga-e-casuale
      VIKUNJA_DATABASE_TYPE: sqlite
      VIKUNJA_DATABASE_PATH: /db/vikunja.db
    volumes:
      - vikunja_files:/app/vikunja/files
      - vikunja_db:/db

volumes:
  vikunja_files:
  vikunja_db:
```

Sostituisci `VIKUNJA_SERVICE_SECRET` con una stringa lunga e casuale, per esempio l'output di `openssl rand -hex 32`. Non perderla: firma gli accessi.

Quando i file sono pronti, mandali al repository:

```bash
git add .
git commit -m "Prima versione"
git push
```

## 2. Crea il sito e il dominio in Sirio

In Sirio:

1. Apri **Siti** → **Nuovo sito**, scrivi il nome `vikunja` e premi **Crea sito**.
2. Nel sito premi **Nuovo dominio**, scrivi `attivita.esempio.it` (usa il tuo dominio) e lascia **TLS** su *HTTPS automatico (Let's Encrypt)*. Premi **Aggiungi**.
3. Premi **Verifica DNS**: deve mostrare l'IP pubblico del tuo server. Se non è così, correggi prima il record `A` dal tuo provider DNS e riprova fra qualche minuto.

## 3. Collega il repository

In Sirio:

1. Apri **Repository** → **Collega repository**.
2. **URL Git**: l'indirizzo del repository che hai appena creato. **Branch di default**: `main`.
3. Repository pubblico: scegli *repository pubblico*. Repository privato: scegli *token HTTPS* o *chiave SSH di deploy* ([come fare](/it/docs/pipeline/#collegare-un-repository)).
4. Premi **Collega**.

## 4. Crea la pipeline

In Sirio:

1. Apri **Pipeline** → **Nuova pipeline**.
2. **Nome**: `vikunja`. **Repository**: quello appena collegato. **Sito**: `vikunja`. **Quando eseguire**: *solo su richiesta* (potrai passare a *a ogni push* più avanti).
3. Nella fase **Rilascio** premi **Rileva da compose**. Sirio trova `compose.yaml` e aggiunge uno step *Docker Compose* con il comando `up`.
4. Premi **Salva pipeline**.

## 5. Esegui la pipeline

1. In **Pipeline** premi **Esegui** accanto a `vikunja`, lascia il branch predefinito e conferma.
2. Guarda il log. Ci vuole meno di un minuto.
3. Quando l'esecuzione diventa verde, apri **Container**: `vikunja` c'è, ed è in esecuzione.

## 6. Collega il dominio al container

1. Torna in **Siti** → `vikunja`.
2. Sulla riga di `attivita.esempio.it` premi **Rotta**.
3. **Path**: `/`. **Container**: `vikunja`. **Porta**: `3456`.
4. Premi **Aggiungi**.

Fatto: Sirio configura il proxy e il certificato HTTPS arriva alla prima visita a `https://attivita.esempio.it`. Non pubblicare nessuna porta nel file compose: la rotta raggiunge il container dentro la rete del server.

## 7. Finisci nel browser

Apri `https://attivita.esempio.it`, premi **Registrati** e crea il tuo account.

Poi chiudi la porta: aggiungi questa riga sotto `environment:` in `compose.yaml`, fai push e riesegui la pipeline.

```yaml
      VIKUNJA_SERVICE_ENABLEREGISTRATION: "false"
```

Da quel momento nessun altro può iscriversi. Per aggiungere persone più avanti rimetti `"true"` per un momento, oppure creale dalla riga di comando del container.

## Aggiornare

Cambia la versione in `image:` (`vikunja/vikunja:2.8` con un tag più recente di [Docker Hub](https://hub.docker.com/r/vikunja/vikunja/tags)) e fai push. Vikunja aggiorna da solo il suo database all'avvio.
Poi, in **Pipeline**, premi di nuovo **Esegui**. Attività e allegati resta dov'è: sta nei volumi nominati, che un rilascio non tocca.

## Backup

Crea un piano di backup del sito in **Backup** e includi i volumi `vikunja_db`, `vikunja_files`: vedi [Backup](/it/docs/backups/). Fallo prima di cominciare a inserire contenuti veri.

## Se qualcosa non funziona

- **Accesso o registrazione falliscono con un errore di rete o "unauthorized"**: `VIKUNJA_SERVICE_PUBLICURL` non è esattamente l'indirizzo che apri nel browser (controlla `https`, il dominio e la `/` finale).
- **Il log dice che non riesce ad aprire il database**: manca la riga `user: "0:0"`.

- **Uno step fallisce o l'esecuzione resta rossa**: apri il log dell'esecuzione in **Esecuzioni**. Un file che Sirio rifiuta (per esempio una riga `ports:` che non può permettere, o una cartella fuori dal repository) è nominato lì, con la chiave. Altro in [File Compose e accesso all'host](/it/docs/security/#file-compose-e-accesso-allhost).

- **`502 Bad Gateway` o un errore di connessione all'indirizzo**: il container non è ancora pronto, oppure la rotta ha il container o la porta sbagliati. Controlla entrambi in **Siti**.

- **Il certificato non arriva**: il DNS deve già puntare al server (**Verifica DNS** nel sito) e le porte 80 e 443 devono essere raggiungibili da Internet.
