[PrestaShop](https://prestashop.com) con un database MySQL. Il negozio si installa da solo al primo avvio: non usi l'installatore web. Circa 20 minuti, in buona parte di attesa.

Qui sotto si dà per scontato che tu abbia già fatto una volta [Prima di iniziare](/it/guides/#prima-di-iniziare): Sirio installato, il proxy attivo e un dominio che punta al tuo server.

## 1. Prepara i file

Crea un repository vuoto su GitHub (con GitLab o Gitea è uguale; meglio **privato**, perché i file conterranno delle password). Poi, sul tuo computer:

```bash
git clone git@github.com:TU/prestashop-sirio.git
cd prestashop-sirio
```

Crea un solo file, `compose.yaml`. Cambia `PS_DOMAIN` con il tuo dominio e `ADMIN_MAIL` con la tua email: diventano il tuo accesso da amministratore.

```yaml title="compose.yaml"
services:
  prestashop:
    image: prestashop/prestashop:9.2.1-apache
    container_name: prestashop
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      PS_DOMAIN: negozio.esempio.it
      PS_ENABLE_SSL: "1"
      PS_INSTALL_AUTO: "1"
      PS_LANGUAGE: it
      PS_COUNTRY: IT
      PS_FOLDER_ADMIN: gestione
      PS_FOLDER_INSTALL: install-da-cancellare
      ADMIN_MAIL: tu@esempio.it
      ADMIN_PASSWD: CAMBIA-MI-1
      DB_SERVER: db
      DB_NAME: prestashop
      DB_USER: prestashop
      DB_PASSWD: CAMBIA-MI-2
    volumes:
      - prestashop_data:/var/www/html

  db:
    image: mysql:8.4
    container_name: prestashop-db
    restart: unless-stopped
    environment:
      MYSQL_DATABASE: prestashop
      MYSQL_USER: prestashop
      MYSQL_PASSWORD: CAMBIA-MI-2
      MYSQL_RANDOM_ROOT_PASSWORD: "1"
    volumes:
      - db_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  prestashop_data:
  db_data:
```

Sostituisci ogni `CAMBIA-MI…` con una tua password, diversa per ognuna. Per averne una buona: `openssl rand -hex 24`. Dove la stessa password compare due volte, usa lo stesso valore in entrambi i posti.

`PS_DOMAIN` è il dominio **senza** `https://`. `PS_FOLDER_ADMIN` è il nome segreto della cartella di amministrazione: scegline uno tuo, è l'indirizzo del tuo back office.

Quando i file sono pronti, mandali al repository:

```bash
git add .
git commit -m "Prima versione"
git push
```

## 2. Crea il sito e il dominio in Sirio

In Sirio:

1. Apri **Siti** → **Nuovo sito**, scrivi il nome `shop` e premi **Crea sito**.
2. Nel sito premi **Nuovo dominio**, scrivi `negozio.esempio.it` (usa il tuo dominio) e lascia **TLS** su *HTTPS automatico (Let's Encrypt)*. Premi **Aggiungi**.
3. Premi **Verifica DNS**: deve mostrare l'IP pubblico del tuo server. Se non è così, correggi prima il record `A` dal tuo provider DNS e riprova fra qualche minuto.

## 3. Collega il repository

In Sirio:

1. Apri **Repository** → **Collega repository**.
2. **URL Git**: l'indirizzo del repository che hai appena creato. **Branch di default**: `main`.
3. Repository pubblico: scegli *repository pubblico*. Repository privato: scegli *token HTTPS* o *chiave SSH di deploy* ([come fare](/it/docs/pipeline/#collegare-un-repository)).
4. Premi **Collega**.

## 4. Crea la pipeline

In Sirio:

1. Apri **Pipeline** → **Nuova pipeline**.
2. **Nome**: `shop`. **Repository**: quello appena collegato. **Sito**: `shop`. **Quando eseguire**: *solo su richiesta* (potrai passare a *a ogni push* più avanti).
3. Nella fase **Rilascio** premi **Rileva da compose**. Sirio trova `compose.yaml` e aggiunge uno step *Docker Compose* con il comando `up`.
4. Premi **Salva pipeline**.

## 5. Esegui la pipeline

1. In **Pipeline** premi **Esegui** accanto a `shop`, lascia il branch predefinito e conferma.
2. Guarda il log. Questa esecuzione avvia solo i container: poi PrestaShop si installa da solo, e servono **altri 3-5 minuti** (apri il log del container `prestashop` in **Container** per seguirlo; ha finito quando dice che sta avviando il web server).
3. Quando l'esecuzione diventa verde, apri **Container**: `prestashop` c'è, ed è in esecuzione.

## 6. Collega il dominio al container

1. Torna in **Siti** → `shop`.
2. Sulla riga di `negozio.esempio.it` premi **Rotta**.
3. **Path**: `/`. **Container**: `prestashop`. **Porta**: `80`.
4. Premi **Aggiungi**.

Fatto: Sirio configura il proxy e il certificato HTTPS arriva alla prima visita a `https://negozio.esempio.it`. Non pubblicare nessuna porta nel file compose: la rotta raggiunge il container dentro la rete del server.

## 7. Finisci nel browser

Apri `https://negozio.esempio.it`: il negozio c'è, con i dati di esempio di una nuova installazione.

L'amministrazione è su `https://negozio.esempio.it/gestione` (il `PS_FOLDER_ADMIN` che hai scelto), con `ADMIN_MAIL` e `ADMIN_PASSWD` del file.

Poi elimina l'installatore, che PrestaShop lascia in una cartella con il nome scelto in `PS_FOLDER_INSTALL`. In **Container** apri il container `prestashop`, premi **Terminale** e scrivi:

```bash
rm -rf /var/www/html/install-da-cancellare
```

## Aggiornare

Gli aggiornamenti di PrestaShop e dei moduli si fanno dal back office. Per le immagini dei container, alza il numero in `image:` (per esempio da `9.2.1-apache` a un tag più recente di [Docker Hub](https://hub.docker.com/r/prestashop/prestashop/tags)) e fai push.
Poi, in **Pipeline**, premi di nuovo **Esegui**. Catalogo, ordini e immagini caricate resta dov'è: sta nei volumi nominati, che un rilascio non tocca.

## Backup

Crea un piano di backup del sito in **Backup** e includi i volumi `prestashop_data`, `db_data`: vedi [Backup](/it/docs/backups/). Fallo prima di cominciare a inserire contenuti veri.

## Se qualcosa non funziona

- **Pagina bianca o 502 subito dopo l'esecuzione**: l'installazione è ancora in corso. Segui il log del container e aspetta.
- **Il negozio si apre senza stili o rimanda a `http://`**: in `PS_DOMAIN` c'è `https://`, oppure un dominio diverso da quello della rotta. Deve essere solo il nome host. Dopo averlo corretto elimina il volume `prestashop_data` e riesegui, perché il valore viene scritto durante la prima installazione.
- **Vuoi ricominciare l'installazione**: in **Volumi** elimina `prestashop_data` e `db_data` (cancella il negozio) e riesegui la pipeline.

- **Uno step fallisce o l'esecuzione resta rossa**: apri il log dell'esecuzione in **Esecuzioni**. Un file che Sirio rifiuta (per esempio una riga `ports:` che non può permettere, o una cartella fuori dal repository) è nominato lì, con la chiave. Altro in [File Compose e accesso all'host](/it/docs/security/#file-compose-e-accesso-allhost).

- **`502 Bad Gateway` o un errore di connessione all'indirizzo**: il container non è ancora pronto, oppure la rotta ha il container o la porta sbagliati. Controlla entrambi in **Siti**.

- **Il certificato non arriva**: il DNS deve già puntare al server (**Verifica DNS** nel sito) e le porte 80 e 443 devono essere raggiungibili da Internet.
