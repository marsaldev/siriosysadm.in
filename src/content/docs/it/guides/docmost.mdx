[Docmost](https://docmost.com) è un wiki open source per documentazione e conoscenza del team. Servono tre container: l'app, PostgreSQL e Redis. Circa 15 minuti.

Qui sotto si dà per scontato che tu abbia già fatto una volta [Prima di iniziare](/it/guides/#prima-di-iniziare): Sirio installato, il proxy attivo e un dominio che punta al tuo server.

## 1. Prepara i file

Crea un repository vuoto su GitHub (con GitLab o Gitea è uguale; meglio **privato**, perché i file conterranno delle password). Poi, sul tuo computer:

```bash
git clone git@github.com:TU/docmost-sirio.git
cd docmost-sirio
```

Crea un solo file, `compose.yaml`. Cambia `APP_URL` con il tuo dominio (tieni `https://`, senza `/` finale).

```yaml title="compose.yaml"
services:
  docmost:
    image: docmost/docmost:latest
    container_name: docmost
    restart: unless-stopped
    depends_on:
      - db
      - redis
    environment:
      APP_URL: https://documenti.esempio.it
      APP_SECRET: CAMBIA-MI-1-at-least-32-characters-long
      DATABASE_URL: postgresql://docmost:CAMBIA-MI-2@db:5432/docmost
      REDIS_URL: redis://redis:6379
    volumes:
      - docmost_storage:/app/data/storage

  db:
    image: postgres:18
    container_name: docmost-db
    restart: unless-stopped
    environment:
      POSTGRES_DB: docmost
      POSTGRES_USER: docmost
      POSTGRES_PASSWORD: CAMBIA-MI-2
    volumes:
      - db_data:/var/lib/postgresql

  redis:
    image: redis:8
    container_name: docmost-redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes", "--maxmemory-policy", "noeviction"]
    volumes:
      - redis_data:/data

volumes:
  docmost_storage:
  db_data:
  redis_data:
```

`APP_SECRET` deve essere di **almeno 32 caratteri**, altrimenti Docmost non parte: usa `openssl rand -hex 32`. La password del database compare due volte (`DATABASE_URL` e `POSTGRES_PASSWORD`): usa lo stesso valore, fatto solo di lettere e numeri (una `@` o una `/` romperebbero l'indirizzo).

Quando i file sono pronti, mandali al repository:

```bash
git add .
git commit -m "Prima versione"
git push
```

## 2. Crea il sito e il dominio in Sirio

In Sirio:

1. Apri **Siti** → **Nuovo sito**, scrivi il nome `docmost` e premi **Crea sito**.
2. Nel sito premi **Nuovo dominio**, scrivi `documenti.esempio.it` (usa il tuo dominio) e lascia **TLS** su *HTTPS automatico (Let's Encrypt)*. Premi **Aggiungi**.
3. Premi **Verifica DNS**: deve mostrare l'IP pubblico del tuo server. Se non è così, correggi prima il record `A` dal tuo provider DNS e riprova fra qualche minuto.

## 3. Collega il repository

In Sirio:

1. Apri **Repository** → **Collega repository**.
2. **URL Git**: l'indirizzo del repository che hai appena creato. **Branch di default**: `main`.
3. Repository pubblico: scegli *repository pubblico*. Repository privato: scegli *token HTTPS* o *chiave SSH di deploy* ([come fare](/it/docs/pipeline/#collegare-un-repository)).
4. Premi **Collega**.

## 4. Crea la pipeline

In Sirio:

1. Apri **Pipeline** → **Nuova pipeline**.
2. **Nome**: `docmost`. **Repository**: quello appena collegato. **Sito**: `docmost`. **Quando eseguire**: *solo su richiesta* (potrai passare a *a ogni push* più avanti).
3. Nella fase **Rilascio** premi **Rileva da compose**. Sirio trova `compose.yaml` e aggiunge uno step *Docker Compose* con il comando `up`.
4. Premi **Salva pipeline**.

## 5. Esegui la pipeline

1. In **Pipeline** premi **Esegui** accanto a `docmost`, lascia il branch predefinito e conferma.
2. Guarda il log. Il primo avvio crea anche il database: dopo che l'esecuzione diventa verde dai un minuto di tempo.
3. Quando l'esecuzione diventa verde, apri **Container**: `docmost` c'è, ed è in esecuzione.

## 6. Collega il dominio al container

1. Torna in **Siti** → `docmost`.
2. Sulla riga di `documenti.esempio.it` premi **Rotta**.
3. **Path**: `/`. **Container**: `docmost`. **Porta**: `3000`.
4. Premi **Aggiungi**.

Fatto: Sirio configura il proxy e il certificato HTTPS arriva alla prima visita a `https://documenti.esempio.it`. Non pubblicare nessuna porta nel file compose: la rotta raggiunge il container dentro la rete del server.

## 7. Finisci nel browser

Apri `https://documenti.esempio.it`. Un modulo crea il tuo spazio di lavoro:

1. Nome dello spazio, il tuo nome, la tua email e una **password robusta**.
2. Premi **Setup workspace**.

Sei l'amministratore. Invita i colleghi dalle impostazioni dello spazio.

## Aggiornare

Il file usa `docmost/docmost:latest`, quindi rieseguire la pipeline scarica la versione più recente solo se chiedi a Docker di aggiornare: nello step Compose della pipeline scrivi `--pull always` in **Argomenti aggiuntivi**. Per una routine più prudente scrivi un numero di versione al posto di `latest` e cambialo quando decidi di aggiornare.
Poi, in **Pipeline**, premi di nuovo **Esegui**. Pagine, allegati e utenti resta dov'è: sta nei volumi nominati, che un rilascio non tocca.

## Backup

Crea un piano di backup del sito in **Backup** e includi i volumi `docmost_storage`, `db_data`, `redis_data`: vedi [Backup](/it/docs/backups/). Fallo prima di cominciare a inserire contenuti veri.

## Se qualcosa non funziona

- **Il container si riavvia di continuo**: apri il suo log in **Container**. Se si lamenta di `APP_SECRET`, il valore è più corto di 32 caratteri.
- **L'editor dice che è offline o non salva in tempo reale**: l'editor usa i WebSocket, che il proxy di Sirio fa passare senza impostazioni. Controlla che `APP_URL` sia esattamente l'indirizzo del browser.
- **Non raggiungi il database dopo aver cambiato la password**: la password viene salvata dentro il database al primo avvio. O la cambi lì, o elimini il volume `db_data` (cancella i dati) e riesegui.

- **Uno step fallisce o l'esecuzione resta rossa**: apri il log dell'esecuzione in **Esecuzioni**. Un file che Sirio rifiuta (per esempio una riga `ports:` che non può permettere, o una cartella fuori dal repository) è nominato lì, con la chiave. Altro in [File Compose e accesso all'host](/it/docs/security/#file-compose-e-accesso-allhost).

- **`502 Bad Gateway` o un errore di connessione all'indirizzo**: il container non è ancora pronto, oppure la rotta ha il container o la porta sbagliati. Controlla entrambi in **Siti**.

- **Il certificato non arriva**: il DNS deve già puntare al server (**Verifica DNS** nel sito) e le porte 80 e 443 devono essere raggiungibili da Internet.
