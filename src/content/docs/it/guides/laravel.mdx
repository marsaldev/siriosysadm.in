Un'applicazione [Laravel](https://laravel.com) con database PostgreSQL, costruita in un container e servita da [FrankenPHP](https://frankenphp.dev). Le migrazioni partono da sole a ogni rilascio. Circa 25 minuti. Sul tuo computer servono PHP 8.2+ e [Composer](https://getcomposer.org).

Qui sotto si dà per scontato che tu abbia già fatto una volta [Prima di iniziare](/it/guides/#prima-di-iniziare): Sirio installato, il proxy attivo e un dominio che punta al tuo server.

## 1. Prepara i file

Crea un repository vuoto su GitHub (con GitLab o Gitea è uguale; meglio **privato**, perché i file conterranno delle password). Poi, sul tuo computer:

```bash
git clone git@github.com:TU/laravel-sirio.git
cd laravel-sirio
```

Parti dal tuo progetto. Se non ne hai ancora uno, creane uno nuovo nella cartella del repository:

```bash
composer create-project laravel/laravel . --no-interaction
```

(Se la cartella non è vuota, crealo in una cartella temporanea e copia tutto nel repository, escluso `.git`.)

Ottieni la chiave dell'applicazione, ti serve fra poco:

```bash
php artisan key:generate --show
```

Stampa qualcosa come `base64:Xk3…=`. Copiala tutta.

Ora aggiungi quattro file al progetto. Prima il `Dockerfile`:

```dockerfile title="Dockerfile"
# 1. Compila CSS e JavaScript
FROM node:22-alpine AS assets
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# 2. Immagine finale: PHP + web server (FrankenPHP)
FROM dunglas/frankenphp:1-php8.4
RUN install-php-extensions pdo_pgsql intl zip opcache pcntl bcmath
COPY --from=composer:2 /usr/bin/composer /usr/local/bin/composer
ENV SERVER_NAME=:80 COMPOSER_ALLOW_SUPERUSER=1
WORKDIR /app
COPY . .
RUN composer install --no-dev --optimize-autoloader --no-interaction
COPY --from=assets /app/public/build public/build
COPY docker/entrypoint.sh /usr/local/bin/app-entrypoint
RUN chmod +x /usr/local/bin/app-entrypoint
ENTRYPOINT ["app-entrypoint"]
CMD ["--config", "/etc/frankenphp/Caddyfile", "--adapter", "caddyfile"]
```

Poi `docker/entrypoint.sh`, che gira a ogni avvio: collega lo storage pubblico e aggiorna il database prima che parta il web server. (Crea la cartella `docker`.)

```sh title="docker/entrypoint.sh"
#!/bin/sh
set -e
php artisan storage:link --force
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
exec docker-php-entrypoint "$@"
```

Poi `.dockerignore`:

```text title=".dockerignore"
.git
vendor
node_modules
.env
storage/logs/*
```

E `compose.yaml`. Sostituisci `APP_KEY` con la chiave che hai copiato e `APP_URL` con il tuo dominio. Scegli una password per il database e scrivila sia in `DB_PASSWORD` sia in `POSTGRES_PASSWORD`.

```yaml title="compose.yaml"
services:
  app:
    build: .
    container_name: laravel
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    environment:
      APP_NAME: Laravel
      APP_ENV: production
      APP_DEBUG: "false"
      APP_KEY: base64:INCOLLA-QUI-LA-CHIAVE
      APP_URL: https://app.esempio.it
      LOG_CHANNEL: stderr
      DB_CONNECTION: pgsql
      DB_HOST: db
      DB_PORT: "5432"
      DB_DATABASE: laravel
      DB_USERNAME: laravel
      DB_PASSWORD: CAMBIA-MI
    volumes:
      - laravel_storage:/app/storage/app

  db:
    image: postgres:17
    container_name: laravel-db
    restart: unless-stopped
    environment:
      POSTGRES_DB: laravel
      POSTGRES_USER: laravel
      POSTGRES_PASSWORD: CAMBIA-MI
    volumes:
      - db_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U laravel -d laravel"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  laravel_storage:
  db_data:
```

Infine, di' a Laravel che sta dietro il proxy di Sirio, così genera link `https://`. In `bootstrap/app.php` sostituisci la funzione `withMiddleware` vuota:

```php title="bootstrap/app.php" ins={2}
    ->withMiddleware(function (Middleware $middleware): void {
        $middleware->trustProxies(at: '*');
    })
```


Quando i file sono pronti, mandali al repository:

```bash
git add .
git commit -m "Prima versione"
git push
```

## 2. Crea il sito e il dominio in Sirio

In Sirio:

1. Apri **Siti** → **Nuovo sito**, scrivi il nome `laravel` e premi **Crea sito**.
2. Nel sito premi **Nuovo dominio**, scrivi `app.esempio.it` (usa il tuo dominio) e lascia **TLS** su *HTTPS automatico (Let's Encrypt)*. Premi **Aggiungi**.
3. Premi **Verifica DNS**: deve mostrare l'IP pubblico del tuo server. Se non è così, correggi prima il record `A` dal tuo provider DNS e riprova fra qualche minuto.

## 3. Collega il repository

In Sirio:

1. Apri **Repository** → **Collega repository**.
2. **URL Git**: l'indirizzo del repository che hai appena creato. **Branch di default**: `main`.
3. Repository pubblico: scegli *repository pubblico*. Repository privato: scegli *token HTTPS* o *chiave SSH di deploy* ([come fare](/it/docs/pipeline/#collegare-un-repository)).
4. Premi **Collega**.

## 4. Crea la pipeline

In Sirio:

1. Apri **Pipeline** → **Nuova pipeline**.
2. **Nome**: `laravel`. **Repository**: quello appena collegato. **Sito**: `laravel`. **Quando eseguire**: *solo su richiesta* (potrai passare a *a ogni push* più avanti).
3. Nella fase **Rilascio** premi **Rileva da compose**. Sirio trova `compose.yaml` e aggiunge uno step *Docker Compose* con il comando `up`.
   Poi, in quello step, scrivi `--build` in **Argomenti aggiuntivi**: fa ricostruire l'immagine dal tuo codice a ogni rilascio.
4. Premi **Salva pipeline**.

## 5. Esegui la pipeline

1. In **Pipeline** premi **Esegui** accanto a `laravel`, lascia il branch predefinito e conferma.
2. Guarda il log. La prima volta costruisce l'immagine (estensioni PHP, Composer, CSS e JavaScript): da 4 a 8 minuti.
3. Quando l'esecuzione diventa verde, apri **Container**: `laravel` c'è, ed è in esecuzione.

## 6. Collega il dominio al container

1. Torna in **Siti** → `laravel`.
2. Sulla riga di `app.esempio.it` premi **Rotta**.
3. **Path**: `/`. **Container**: `laravel`. **Porta**: `80`.
4. Premi **Aggiungi**.

Fatto: Sirio configura il proxy e il certificato HTTPS arriva alla prima visita a `https://app.esempio.it`. Non pubblicare nessuna porta nel file compose: la rotta raggiunge il container dentro la rete del server.

## 7. Finisci nel browser

Apri `https://app.esempio.it`: la pagina di benvenuto di Laravel c'è, con il database già migrato.

D'ora in poi la routine è: cambi il codice, `git push`, **Esegui** la pipeline. Per renderla automatica imposta **Quando eseguire** su *a ogni push* e aggiungi il webhook come spiegato in [Pipeline](/it/docs/pipeline/#avvio-automatico-da-webhook).

Per lanciare un comando Artisan (un seeder, creare un utente) apri il container `laravel` in **Container**, premi **Terminale** e scrivi per esempio `php artisan db:seed --force`.

## Aggiornare

Fai `git push` delle modifiche ed esegui la pipeline: Sirio ricostruisce l'immagine dal nuovo codice, sostituisce il container e le migrazioni partono all'avvio.
Poi, in **Pipeline**, premi di nuovo **Esegui**. Il database e i file in `storage/app` resta dov'è: sta nei volumi nominati, che un rilascio non tocca.

## Backup

Crea un piano di backup del sito in **Backup** e includi i volumi `db_data`, `laravel_storage`: vedi [Backup](/it/docs/backups/). Fallo prima di cominciare a inserire contenuti veri.

## Se qualcosa non funziona

- **"No application encryption key has been specified"**: `APP_KEY` è ancora il segnaposto, o ha perso l'inizio `base64:`.
- **La build fallisce a `npm install` / `npm run build`**: apri il log. Se il tuo progetto non usa Vite, togli la prima fase del `Dockerfile` e la sua riga `COPY --from=assets`.
- **Il container si riavvia di continuo**: apri il suo log. Una tua migrazione fallisce, oppure la password del database è diversa fra `DB_PASSWORD` e `POSTGRES_PASSWORD`.
- **Le pagine non hanno stili, o i link sono `http://`**: manca la riga `trustProxies` di `bootstrap/app.php`, oppure `APP_URL` non inizia con `https://`.

- **Uno step fallisce o l'esecuzione resta rossa**: apri il log dell'esecuzione in **Esecuzioni**. Un file che Sirio rifiuta (per esempio una riga `ports:` che non può permettere, o una cartella fuori dal repository) è nominato lì, con la chiave. Altro in [File Compose e accesso all'host](/it/docs/security/#file-compose-e-accesso-allhost).

- **`502 Bad Gateway` o un errore di connessione all'indirizzo**: il container non è ancora pronto, oppure la rotta ha il container o la porta sbagliati. Controlla entrambi in **Siti**.

- **Il certificato non arriva**: il DNS deve già puntare al server (**Verifica DNS** nel sito) e le porte 80 e 443 devono essere raggiungibili da Internet.
